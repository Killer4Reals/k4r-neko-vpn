# Проверка туннеля в Docker

Зачем: убедиться, что сервер из подписки реально поднимает туннель и работает,
**не трогая систему**. Клиент живёт в контейнере и слушает SOCKS только на
`127.0.0.1`, поэтому маршруты Windows, WFP-фильтры и запущенные игры не
затрагиваются — если контейнер упал, интернет и игра этого не заметят.

## Что нужно

- Docker Desktop (Linux-контейнеры), запущен
- JSON подписки провайдера: массив конфигов вида
  `[{"remarks": "...","outbounds":[...]}, ...]` (то, что отдаёт панель с
  заголовком `X-HWID`)
- `python` для генератора конфигов Xray

## Порядок

```bash
# 1. конфиг клиента из подписки (по одному узлу на страну)
python tools/tunnel-check/mk-configs.py C:/path/sub.json de nl us jp

# 2. поднять контейнеры: 127.0.0.1:10801/10802/... → SOCKS внутри контейнера
docker run -d --name k4r-de -p 127.0.0.1:10801:1080 \
  -v "$PWD/out/xray-de1.json:/etc/xray/config.json:ro" teddysun/xray:latest

# 3. проверить выход: IP должен быть чужим, а не провайдера
curl -s --proxy socks5h://127.0.0.1:10801 https://api.ipify.org
```

Скрипт `check.py` делает то же самое одной командой: поднимает по контейнеру на
узел, мерит задержку и скорость, печатает таблицу и всё убирает.

## Как читать результат

| что | норма |
|---|---|
| IP через туннель | не совпадает с IP без туннеля |
| задержка TLS | +30…+90 мс к прямой — это дорога до сервера |
| скорость | 60–85 % от прямой: столько забирает шифрование и маршрут |
| страна | совпадает с обещанной в имени сервера |

## Важное

- Конфиги — это чужие ключи: каталог `out/` не коммитим.
- Проверка ничего не меняет в системе, но **трафик расходует** подписку.
- `socks5h` (с `h`) обязателен: DNS тоже должен идти через туннель, иначе
  страна выхода получается не той, что ожидалось.
