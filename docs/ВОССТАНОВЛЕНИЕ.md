# Если всё сломалось: восстановление с нуля

Этот файл — на случай, когда ноутбук умер, папка потерялась или через год надо
выпустить обновление, а ничего не помнишь. Порядок такой, что его можно выполнить
без остальных документов.

## Что нельзя потерять

| Что | Где лежит | Зачем |
|---|---|---|
| Ключ подписи APK `k4r-release.jks` | `%LOCALAPPDATA%\Android\keys\` + копия в `Documents\k4r-keys\` + секрет `ANDROID_KEYSTORE_B64` в GitHub | Без него обновление не встанет поверх установленного приложения |
| Пароль ключа | `k4r-release.pass.txt` рядом с ключом + секреты `ANDROID_KEYSTORE_PASS` / `ANDROID_KEY_PASS` | Ключ без пароля бесполезен |
| Ссылка подписки | в приложении (ПК: `%APPDATA%\ink.k4r.nekoneko.vpn\state.json`, поле `sub_url`) | Вернуть доступ к серверам |
| ID устройства (HWID) | там же, поле `hwid` | Провайдер не сочтёт новое устройство за ещё одно |

Три копии ключа — не паранойя: ключ нельзя «перевыпустить», можно только
потерять. Если он пропал, старые установки придётся удалять и ставить заново.

## Восстановить разработку на новой машине

```powershell
git clone https://github.com/Killer4Reals/k4r-neko-vpn.git            # ПК-клиент
git clone https://github.com/Killer4Reals/k4r-neko-vpn-android.git    # Android
```

**Windows:**

1. Node.js 20+, Rust (stable), WebView2 (в Windows 11 уже есть).
2. `cd app && npm ci`
3. Ядро: положить `sing-box.exe` (v1.14.4, windows-amd64 с github.com/SagerNet/sing-box)
   в `app/src-tauri/resources/bin/`. В git его нет — он весит 80 МБ.
4. `npm run tauri build` → установщик в `app/src-tauri/target/release/bundle/nsis/`.
5. Тесты: `cd app/src-tauri && cargo test` (55), `cd app && npm test` (25).

**Android:**

1. JDK 21, Android SDK 35, NDK 27.1.12297006, Go 1.23 (для ядра).
2. `powershell -ExecutionPolicy Bypass -File scripts/build-libbox.ps1` — соберёт
   `libbox.aar` в `app/libs/`. Либо скачать его из релиза `libbox-1.14.4` этого
   же репозитория.
3. `keystore.properties` рядом с `settings.gradle.kts`:
   ```
   storeFile=C:/Users/<ты>/AppData/Local/Android/keys/k4r-release.jks
   storePassword=...
   keyAlias=k4r
   keyPassword=...
   ```
   Без него `assembleRelease` соберёт `app-release-unsigned.apk` — поставить нельзя,
   и это видно сразу.
4. `./gradlew testDebugUnitTest assembleRelease` → `app/build/outputs/apk/release/`.

## Выпустить обновление

Релиз собирается **тегом**, а не руками:

```bash
# ПК
git tag -a v1.5.0 -m "K4R Neko VPN 1.5.0" && git push origin v1.5.0
# Android
git tag -a v1.1.0-android -m "Android 1.1.0" && git push origin v1.1.0-android
```

Дальше CI сам: скачивает ядро, собирает, проверяет подпись APK (`CN=K4R Neko VPN`),
создаёт релиз и прикладывает файлы. Если подпись не наша, сборка падает — так
задумано: иначе обновление не встанет ни у кого.

## Обновить ядро туннеля

- **ПК:** Настройки → «Ядро туннеля» → «Обновить ядро». Скачивается официальный
  sing-box, проверяется запуском (`sing-box version` должен ответить запрошенной
  версией) и кладётся в `%APPDATA%\ink.k4r.nekoneko.vpn\core\sing-box.exe`.
  Встроенное не трогается, «Вернуть встроенное» удаляет обновление.
- **Android:** ядро вшито в APK (`libbox.aar`) — обновление приходит новым APK.
- **CI:** поднимите `$ver` в `.github/workflows/release.yml` и пересоберите тегом.

## Признаки, что что-то не так

| Симптом | Что смотреть |
|---|---|
| «Ошибка: сервер не ответил» на всех серверах | провайдер сменил протокол → обновить ядро (ПК); на Android — новый APK |
| APK не ставится поверх | подпись другим ключом: проверить `apksigner verify --print-certs` |
| Релиз собрался, но файла нет | шаг «приложить к релизу»: там `gh release upload` |
| Нет серверов, в ответе заглушка | лимит устройств у провайдера: удалить лишнее устройство в кабинете |

## Что проверить после восстановления

1. `cargo test`, `npm test`, `./gradlew testDebugUnitTest` — зелёные.
2. Тег → релиз собрался и файлы на месте.
3. Туннель поднимается, «Защищено» появляется только после ответа через туннель.
4. На телефоне APK ставится поверх прошлой версии.
