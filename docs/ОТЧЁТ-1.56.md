# Отчёт 1.56.0 — P0 после публичной beta

Дата: 2026-11-26. Статус: **опубликовано**. Установщик собран, загружен и проверен
скачиванием; `version.json` отдаёт 1.56.0 и совпадающий SHA-256.

## Что закрыто

| P0 | Было в 1.55 | Стало в 1.56 |
| --- | --- | --- |
| Честность паспорта | `quality: good` у всех живых узлов, `100 A` без замера | `quality/score/grade` удалены; только измеренный пинг и свежесть, иначе «нет замера» |
| Статус защиты | «Защищено» при split-only и выключенном kill-switch | «Защищено» только полный туннель + реально активный kill-switch; иначе «только выбранные» / «без kill-switch» |
| Failover | падение `sing-box` оставляло «Отключено» | выбор другого живого узла, красный баннер с причиной; после восстановления — зелёный с «Понятно» |
| Секреты | ссылка подписки с токеном видна целиком | скрыта как пароль, копирование/QR используют полную; журнал сырой без ложного обещания редакции |
| Производительность | глобус крутил RAF постоянно, простой Главной ~5.6% ядра | цикл ограничен 8 с/900 кадров, не перезапускается от смены статуса; декор Главной статичен; 1.9–2.6% |

## Доказательства

- `npx tsc --noEmit` — exit 0.
- `npx vitest run` — **36 файлов, 284 теста, exit 0**; в том числе `failover.test.ts` (6) и `protection.test.ts` (3).
- `cargo test --lib` — **168 passed, 4 ignored, exit 0**. Полный `cargo test` дополнительно собирает bin-тест, который требует elevation и падает с `os error 740`; это ограничение манифеста, не библиотеки.
- Ручной failover: подключённый туннель, принудительное завершение `sing-box`; приложение сменило узел, туннель остался жив, появился красный баннер, после восстановления — зелёный «Туннель переключён…» и кнопка «Понятно» (проверено через UIA Invoke).
- Простой Главной: 5.6% ядра до правок, **1.89–2.63%** после (лучший замер GPU 1.16/renderer 0.67, худший GPU 1.42/renderer 0.72) за 5 с после 18–30 с бездействия; курсор уведён за пределы окна. Для сравнения «Настройки» — 1.15%.
- Установщик: `K4R.Neko.VPN_1.56.0_x64-setup.exe`, **29 672 359 байт**,
  SHA-256 `5774e8c565ee43689f48aeac95540744d6ddb9c604a518d22fbe2a9f22cbdda8`.
  Подпись: `NotSigned` (как и 1.55), SmartScreen будет предупреждать.
- Версия `1.56.0` в `app/package.json`, `Cargo.toml`, `tauri.conf.json`, `version.json`;
  `ProductVersion` exe — 1.56.0.

## Ограничения

- Failover остаётся фронтендным: при закрытом окне Rust-супервизор перезапускает **тот же** узел. Полноценный фоновый failover — 1.57.
- Нет E2E, нагрузочных и визуальных регрессионных тестов; это по-прежнему ручная приёмка.
- Журнал сырой; токены/адреса в нём не вырезаются. Это написано в UI и упаковке.
- Остаточный простой Главной 1.9–2.6% не ноль; на слабых машинах разница с «Настройками» останется.
- Все 11 узлов не проверялись по отдельности: в одном прогоне они кратко отвечали «не отвечает», в следующем Лондон дал 32 мс и паспорт заполнился. Это не доказательство исправности каждого узла.
- Независимое ревью другой ролью запускалось, но subagent-инфраструктура не завершила задачу (два запуска висели в `working`); формально пункт AGENTS «независимая проверка» **не закрыт**. Поэтому это кандидат, а не «готово».

## Откат

Вернуть фронтенд на тег `v1.55.0`; схема данных и бэкенд не менялись,
пользовательские настройки не мигрируются. Единственное последствие — снова
появятся выдуманный `quality` и старый цикл глобуса.
