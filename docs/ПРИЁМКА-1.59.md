# Приёмка 1.59: перезапуск без ложного обрыва

Дата: 2026-11-27. Предмет: поведение из `docs/ADR-1.58.md` (п. 1 и 5).
Цель — убедиться, что интерфейс не путает намеренный перезапуск ядра с
обрывом и не запускает второй failover поверх супервизора.

## Что уже проверено (до живой приёмки)

- `scripts/check.ps1` — зелёный: tsc, vitest (288), vite build, cargo test
  (184 passed, 5 ignored).
- Юнит-тесты: `starting` не выдаётся за `idle`; `error` под живым супервизором
  не выдаётся за смерть; мигание сети A→B→A в тихом окне не перезапускает
  ядро; адрес TUN в конфиге совпадает с константой сторожа.
- Runtime-проверки ниже требуют установленной сборки с этими правками и
  живой сети. Их нельзя выполнить на release-сборке, собранной до коммита
  `f0402e2`.

## 1. Установка

Кандидат: `release/K4R.Neko.VPN_1.57.1_x64-setup.exe`,
SHA-256 `187d9d0a0cdcf64e853a9a10a94be8ebc66c78e42c4f1fec5d01b2f84f137d5d`,
29 670 183 байта, FileVersion 1.57.1, подпись отсутствует.

- [ ] Установить этот установщик поверх 1.56.0.
- [ ] Версия в настройках совпадает с установщиком.
- [ ] Серверы, подписка и настройки прошлой версии на месте.

## 2. Падение ядра под супервизором

Подготовка: подключиться, открыть «Историю», включить экспорт логов.

- [ ] В диспетчере задач завершить `sing-box.exe`.
- [ ] В течение 2 секунд статус — «подключаемся», не «ошибка» и не «обрыв».
- [ ] Через 10–15 секунд туннель снова работает, сайты открываются.
- [ ] В «Истории» нет события «Отключился» и нет смены узла, которой не было.
  Допустимо событие о переподключении, если оно есть в продукте.
- [ ] Повторить три раза: сообщение меняется на «переподключаемся (n/3)»,
  после третьего отказа — честная ошибка, не бесконечный цикл.
- [ ] После окончательной ошибки автопереключение срабатывает один раз, а не
  по кругу; в журнале нет двух одновременных запусков ядра.

## 3. Смена узла

- [x] Переключить узел на главном экране при поднятом туннеле.
- [x] Видно «подключаемся», затем «подключено»; нет промежуточного «обрыв».
- [x] В «Истории» ровно одно переключение A → B.
- [ ] Повторить выбор узла из меню трея: результат тот же, окно не
  замирает дольше секунды. Не проверено: в момент приёмки владелец смотрел
  видео в Яндекс Браузере на весь экран, и открывать меню трея поверх него
  было бы вмешательством. Путь бэкенда у меню и окна общий (`pick_server`).

## 4. Смена сети и мигание

- [ ] При поднятом туннеле переключиться с Wi-Fi на Ethernet (или наоборот):
  приложение переподключается само, без ручного вмешательства.
- [ ] Быстро выключить и включить Wi-Fi в пределах ~15 секунд: лишнего
  перезапуска и смены узла нет.
- [ ] Переход в TUN и обратно не считается сменой сети.

## 5. Трей и мини-плеер

- [ ] Подключиться, затем выключить туннель из меню трея при открытом окне.
- [ ] Окно показывает «отключено» и НЕ поднимает туннель обратно само.
- [ ] То же из мини-плеера.
- [ ] Клик по трею во время «подключаемся» выключает туннель, а не запускает
  второй.

## 6. Выход и осиротевшее ядро

- [ ] Запустить подключение и сразу выйти из приложения (в первые секунды).
- [ ] В диспетчере задач не осталось `sing-box.exe`.
- [ ] Принудительно завершить приложение при поднятом туннеле, запустить
  снова: приложение стартует, туннель поднимается, адаптер не занят.
- [ ] Запустить второй экземпляр: открывается окно первого, второго ядра в
  диспетчере нет.

## Результаты 1.57.1 (2026-11-27, 15:05–15:15)

Проверено вживую на установленной 1.57.1, туннель поднят, split «только
выбранные»:

- Смена Финляндия → Нидерланды: ядро сменилось (PID 8148 → 17664), через
  ~2 с в «паспорте» Нидерланды; одновременно работало одно ядро. Снимок
  `screens/acceptance-1.59-switch-connecting.png` показывает «Подключение…»,
  `screens/acceptance-1.59-switch-connected.png` — «Туннель активен» и
  Финляндию после обратной смены.
- Обратная смена Нидерланды → Финляндия: PID 13072, статус снова
  «Подключение…» → «Туннель активен», в «Истории» одна запись
  «Переключил узел: Нидерланды → Финляндия».
- Клик по уже выбранному узлу: PID не менялся (13072), лишней записи нет.
- Минус прошлой сборки подтверждён: до 1.57.1 клик менял только подпись,
  ядро оставалось прежним. Это и был дефект, ради которого выпущен 1.57.1.

Не проверено в этом прогоне и остаётся открытым: пункт трея, три отказа
супервизора с честной ошибкой, смена сети/Wi-Fi, выключение из трея и
мини-плеера, выход в первые секунды и уборка осиротевшего ядра. Их нельзя
считать принятыми по этому отчёту.

## 7. Что считать провалом

- Два одновременных `sing-box.exe` после одного действия.
- Смена узла без действия пользователя во время восстановления.
- Туннель, поднявшийся после намеренного выключения из трея.
- `sing-box.exe` с TUN после полного выхода.
