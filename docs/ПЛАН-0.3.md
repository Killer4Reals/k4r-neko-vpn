# План на остаток 0.3

Состояние на 15.11.2026, 13:20. Живые тесты туннеля приостановлены: на машине
идёт игра, а запуск и остановка туннеля рвут её соединение (это не античит и не
наша запись в игру — просто смена маршрутов на время теста).

## Готово в коде, ждёт проверки вживую

1. Режим «Только выбранные программы»: в туннель идут только отмеченные
   программы, всё остальное — напрямую. Локальная сеть остаётся локальной.
2. Защита от пустого смысла: если список пуст, подключение честно отказывается
   с текстом «список пуст — добавь программу». Иначе приложение показывало бы
   «Защищено», не защищая ничего, и зря поднимало бы адаптер.
3. DNS-сервер туннеля: адрес, `https://…` (DoH) или `tls://…`, плюс быстрые
   кнопки Cloudflare / Google / Quad9.
4. Сворачивание в трей по кнопке «—» (в дополнение к крестику).
5. Всплывающая карточка в углу окна вместо системных уведомлений.
6. Пресет Zapret запоминается.
7. Все консольные вызовы скрыты: чёрное окно при входе в «Защиту» больше не
   появляется.

## Что осталось проверить (нужна пауза в игре, ~3 минуты)

- Подключение в режиме «Только выбранные» с одной программой в списке:
  она идёт через VPN, остальные — напрямую.
- DNS внутри туннеля: DoH через прокси и обычный UDP через роутер. В тестовом
  прогоне DoH через сервер не ответил (сервер, похоже, не пускает 1.1.1.1:443),
  поэтому нужен прогон с UDP-вариантом и выбор рабочего по умолчанию.
- Сворачивание в трей и возврат окна кликом по котику.
- Карточка в углу окна при подключении и обрыве.

## Ответ по Zapret 2 DEV

Посмотрел его настройки (`Documents\Zapret\Dev`, таблица `settings`):

- **DNS** — у него включён DoH (`doh_enabled: true`) и свой список серверов.
  Это мы уже умеем: поле «DNS-сервер туннеля» принимает адрес, DoH-ссылку и DoT.
  Отличие: Zapret меняет DNS системы целиком, мы — только DNS внутри туннеля.
  Менять системный DNS мы не будем: если приложение упадёт, человек останется
  с чужим DNS и без интернета.
- **Telegram proxy** — у Zapret это локальный прокси (порт 1353, режим socks5),
  к которому подключается сам Telegram. У нас роль этого прокси играет сам
  туннель: добавил Telegram в список «В VPN» — он идёт через VPN. Отдельный
  MTProto-прокси наш движок не умеет (в нём нет MTProto), и делать свой ради
  дублирования смысла нет.

## Порядок работ

1. Доделать DNS в режиме «только выбранные» (UDP через прокси как основной,
   DoH как выбор).
2. Собрать 0.3.1, поставить в `dist` и на рабочий стол.
3. Прогнать проверки из списка выше одной короткой серией.
4. Обновить отчёт и ADR, если DNS-схема изменится.
