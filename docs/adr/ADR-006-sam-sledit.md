# ADR-006. Клиент сам следит за сетью, но не решает за человека

Дата: 17.11.2026. Версия: Windows 1.5.0, Android 1.1.0.

## Что решали

Туннель живёт в двух средах, которые меняются без нашего участия: сеть на ПК
(кабель ↔ Wi-Fi, выход из сна, другой роутер) и телефон с его экономией
батареи. Пользователь ждёт, что «включённый VPN» остаётся включённым; на деле
после смены сети sing-box продолжает держать старый маршрут, соединение
умирает, а приложение показывает «Защищено». Это худший вид вранья — человек
думает, что защищён.

Второй случай: сервер формально поднят, но данные через него не идут
(перегружен, фильтруется по пути). Перебор при запуске такое не ловит.

## Варианты

1. **События Windows (COM, `NetworkListManager`)** — точнее и мгновенно, но
   тянет новые зависимости и COM-инициализацию в фоновом потоке. Крейты
   недоступны (прокси crates.io мёртв), а писать COM-обвязку вручную — это
   сотни строк `unsafe` ради того, что опрос даёт бесплатно.
2. **Опрос локального адреса выхода раз в 5 секунд** — `UdpSocket::connect`
   выбирает маршрут, но не отправляет пакетов. Смена маршрута по умолчанию
   меняет этот адрес. Ноль зависимостей, работает при заблокированной сети.
3. **Ничего не делать, оставить ручное переподключение** — дешевле, но именно
   это и есть та проблема, из-за которой писали ADR.

Выбран вариант 2.

## Решения

**Автоподключение** (`store::should_autoconnect`): только при трёх условиях —
галочка включена, серверы есть, туннель не поднят. По умолчанию выключено:
портативная программа не должна лезть в сеть без просьбы. Подключение
запускается через 1.5 с после старта, чтобы окно уже было на экране.

**Сторож сети** (`netwatch`): адрес сменился на другой непустой → перезапуск
туннеля, но **только если он был поднят**. Если человек выключил VPN, сторож
молчит: «не подключайся» — это тоже команда. После перезапуска 20 секунд
тишины, иначе одна заминка даёт лавину переподключений.

**Сторож качества** (`health`): раз в 15 секунд `http://1.1.1.1/cdn-cgi/trace`
внутри туннеля. Три неудачи подряд → следующий сервер из подписки, потом минута
тишины. Порог три, а не один: одиночная заминка на секунду — это нормальная
жизнь сети, а не повод дёргать сервер. Выбор владельца при обходе **не
перезаписывается**: иначе «само переключилось» превратилось бы в «само
поменяло мою настройку».

**Трей** (`tray_menu`, `pick_server`): до шести серверов в меню значка с
отметкой выбранного, подсказка значка = состояние + сервер. Меню пересобирается
только при смене числа серверов или выбранного — иначе оно дёргалось бы на
каждом сохранении состояния (а оно сохраняется с задержкой 700 мс).

**Причина отказа** (`engine::failure_reason`): сначала проверяем, есть ли
вообще интернет (пустой маршрут → «нет интернета»), потом TCP-дозвон до
`server:port` из конфига (не дозвонились → «сервер не отвечает»). Код выхода
движка человеку ничего не говорит; он остаётся в журнале, но не в интерфейсе.

**Android**: `Net.batteryRestricted` спрашивает систему, а не модель телефона;
список строгих производителей — только добавка второй строки, не замена
системной настройки. `Net.verdict`: нет сети → виновата сеть, даже если ядро
сказало «connection refused».

## Чем платим

- Опрос адреса: 5 секунд задержки на реакцию и один системный вызов на круг.
  Смена сети внутри одной подсети (тот же шлюз) не заметна — тогда спасает
  сторож качества.
- Сторож качества тратит один запрос в 15 секунд через туннель: ~5 КБ в час.
  Для чужого сервера это вежливо, для лимита трафика незаметно.
- Порог «три неудачи» означает до 45 секунд плохого соединения перед
  переключением. Снижать до одной — получить переключения на каждой заминке.

## Как проверить руками

1. Включить «Подключаться при запуске», перезапустить приложение → туннель
   поднимается сам, окно уже на экране.
2. Переключить Wi-Fi на кабель при работающем туннеле → в журнале
   переподключение, в трее снова «Защищено».
3. Выключить VPN, сменить сеть → туннель не включается.
4. Выключить сервер на стороне провайдера (или взять неработающий профиль) →
   через ~45 секунд берётся следующий сервер; выбор в списке не меняется.
5. Отключить сеть целиком и нажать включение → «нет интернета: проверь Wi-Fi
   или кабель», а не «движок завершился с кодом 1».
