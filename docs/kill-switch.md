# Kill-switch на уровне Windows (WFP)

Коротко: обычный kill-switch держится, пока жив процесс приложения (TUN-адаптер
и «держащий» конфиг ядра). Если процесс умирает целиком, адаптер исчезает и
трафик уходит наружу. Этот документ описывает вторую линию защиты — фильтры
Windows Filtering Platform (WFP), которые живут в ядре и снимаются системой
только вместе с сессией процесса-хранителя.

## Как устроено

- **Helper** — тот же `K4R Neko VPN.exe`, запущенный с аргументом `--wfp-helper`.
  Отдельного бинаря нет: обновлять и подписывать один файл проще.
- Helper открывает **динамическую** сессию WFP (`FWPM_SESSION_FLAG_DYNAMIC`).
  Это значит: какие бы фильтры он ни добавил, при завершении сессии — включая
  аварийное — BFE удалит их сам. Вечных фильтров после ребута не остаётся.
- Helper не умирает вместе с GUI: он отдельный процесс и не в job-объекте
  приложения. **Fail-closed**: если GUI упал, блокировка остаётся.
- Приложение не трогает фильтры напрямую. Оно говорит helper'у по named pipe
  `\\.\pipe\k4r-neko-killswitch`: `apply`, `disable`, `status`, `shutdown`.
- Pipe защищён DACL: полный доступ только у SYSTEM, администраторов и
  владельца; остальным — отказ. После подключения helper дополнительно
  проверяет, что клиент повышен (`TokenElevation`), иначе рвёт соединение и
  пишет в журнал PID клиента.

## Правила

Sublayer `K4R Neko VPN kill-switch`, вес `0xFFF0` (выше системных).
Слои: `ALE_AUTH_CONNECT_V4` / `ALE_AUTH_CONNECT_V6`.

| # | Действие | Вес | Условия |
|---|---|---|---|
| 1–2 | PERMIT | 15 | loopback `127.0.0.0/8`, `::1/128` |
| 3–4 | PERMIT | 14 | приватные сети `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `fc00::/7`, `fe80::/10` |
| 5 | PERMIT | 13 | app-id = абсолютный путь `sing-box.exe` (движок звонит на сервер напрямую) |
| 6b | PERMIT | 12 | local `172.19.0.1/32` — страховка на адрес TUN |
| 6 | PERMIT | 12 | local LUID интерфейса TUN — **ставится динамически** watcher'ом |
| 7–8 | PERMIT | 11 | резолвер: UDP/53 и TCP/53, только своё семейство адресов |
| 9 | PERMIT | 11 | резолвер: TCP/853, если включён DoT |
| 10 | PERMIT | 10 | DoH: TCP/443 **только на явно заданный IP** |
| 11 | **BLOCK** | 1 | без условий — всё остальное |

Порядок: BLOCK ставится первым и отдельно, разрешения — транзакцией. Если
транзакция упала, старый набор остаётся, BLOCK никуда не девается.

**Почему #6b в стартовом плане.** Пока TUN нет, `172.19.0.1` никому не
принадлежит — правило безвредно. Когда TUN появляется, watcher
(`NotifyIpInterfaceChange`, fallback — опрос раз в 100 мс) добавляет #6 по LUID
за единицы миллисекунд; #6b страхует окно до этого момента. #6b — кандидат на
удаление после живой проверки, если LUID-правило стабильно.

## Что делать, если интернет пропал

1. Включите VPN — трафик пойдёт через туннель.
2. Или выключите галку «Kill-switch» в настройках.
3. Если приложение сломано: `K4R Neko VPN.exe --wfp-off` (от администратора).

`--wfp-off` сначала просит helper выйти по каналу (`shutdown`) — тот снимает
фильтры и завершается. Если канал завис, берёт PID из
`%LOCALAPPDATA%\K4R-Neko-VPN\wfp-helper.pid` и завершает процесс: динамическую
сессию снимает система. Код возврата 0 — сработало, 1 — не получилось.

## Ручной чек-лист приёмки

Выполнять на машине с правами администратора.

1. **Блокировка при мёртвом туннеле.** Включить kill-switch, VPN не включать.
   `curl -m 5 https://example.com` — не проходит. `curl -m 5 http://127.0.0.1:1354`
   (или любой локальный порт) — отвечает. `nslookup example.com` — работает
   (DNS разрешён только к резолверу).
2. **Туннель поднимается сразу.** Не выключая kill-switch, включить VPN.
   Через 1–2 с (на практике — миллисекунды, событие `NotifyIpInterfaceChange`)
   интернет работает. В журнале helper'а: `TUN LUID <x> обнаружен, правило #6
   добавлено`.
3. **Падение GUI — fail-closed.** Подключить VPN, затем в диспетчере задач
   снять процесс `K4R Neko VPN.exe` (именно GUI). Трафик наружу не идёт,
   helper жив, фильтры на месте. Запустить приложение снова: галка
   «Kill-switch» **остаётся включённой**, блокировка держится, статус
   «Защита на уровне ОС». Интернет не возвращается сам — только после явного
   «Отключить kill-switch»/«Отключить VPN» (или `--wfp-off`).
4. **Падение helper'а — снятие блокировки.** Убить helper. Интернет
   возвращается без перезагрузки: система сняла динамическую сессию. Если GUI
   жив, watchdog поднимает helper заново за секунды (жёлтая плашка →
   зелёная), и кейс «снято» не показывается.

   **Красная плашка «Защита снята» достижима только при отказе watchdog'а**, с
   конкретной причиной в тексте:
   - helper убит вместе с GUI (оба процесса сняты через диспетчер задач), и при
     следующем старте helper не поднялся;
   - `spawn` упал: UAC отклонён, `ERROR_ACCESS_DENIED`, exe пропал/заменён
     антивирусом;
   - шина занята чужим процессом (наше `FILE_FLAG_FIRST_PIPE_INSTANCE`).

   Никакого generic «сбой» нет: в плашке — системная ошибка, с которой можно
   что-то сделать.
5. **Непривилегированный процесс не может снять защиту.** Из cmd обычного
   пользователя:
   ```
   taskkill /F /PID <helper_pid>
   ```
   Ожидается `Access is denied` (helper запущен с правами администратора).
   Затем — попытка отправить `disable` в канал из непривилегированного
   процесса: helper рвёт соединение и пишет в журнал
   `отказано клиенту без прав администратора, pid <pid>`.
6. **Пересборка при смене сервера.** Переключить сервер и переподключиться:
   фильтры пересобираются одной транзакцией, BLOCK не исчезает ни на миг,
   в журнале нет `CRITICAL`.

## Известные ограничения (осознанные)

- **Сетевые проверки приложения заблокированы при kill-switch on + VPN off.**
  Проверка обновлений и загрузка подписки идут напрямую, а не через tуннель,
  поэтому BLOCK их не пропускает. Это by design: апдейтер не должен обходить
  защиту. Разблокируются при подключении VPN или выключении kill-switch; в
  интерфейсе кнопка проверки обновлений в этом состоянии пишет
  «Заблокировано kill-switch: подключите VPN или выключите блокировку».
- **Zapret при kill-switch on + VPN off не работает.** `winws2` обрабатывает
  трафик через физический интерфейс, а не через TUN, поэтому попадает под
  BLOCK. TODO: либо отдельный permit по app-id `winws2.exe`, либо
  предупреждение в интерфейсе. Пока — только этот документ.
- **DoH по имени не разрешается.** Если резолвер задан как
  `https://cloudflare-dns.com/dns-query`, IP неизвестен, и правило на 443 не
  ставится. DoH при этом работает через туннель; при kill-switch on + VPN off
  он недоступен. Для работы без VPN задайте резолвер IP-адресом.
- **Убийство helper'а — это escape, а не дыра.** Helper — процесс
  администратора, убить его может только администратор. Такой сценарий нужен
  ровно для случая «GUI сломался, helper завис»; систему это не ослабляет.
