# Что менялось

## Windows 1.13.0 — WARP в один клик

- **Кнопка «Включить WARP».** Приложение само генерирует ключи WireGuard,
  регистрирует бесплатное устройство в Cloudflare (без аккаунта) и добавляет
  готовый профиль в список серверов как резервный. Копировать `.conf` и ставить
  wgcf больше не нужно.
- Разбор ответа Cloudflare терпит оба формата (плоский объект и `result`),
  `reserved` берётся из `config.client_id` — без него WARP не поднимается.
- Ограничение частоты (429) объясняется словами, а не кодом.
- Тесты: Rust **117** (+2 живых прогона под `#[ignore]`), фронтенд 77.

## Windows 1.12.0 — WireGuard/WARP и резервные серверы

- **WireGuard-профили.** В «Серверах» появилась кнопка «Добавить WireGuard / WARP»:
  вставляешь текст `.conf`, приложение делает из него обычный сервер. Работают и
  WARP, и любые WireGuard-серверы; sing-box поднимает их так же, как VLESS.
- **Резервные серверы.** У каждого сервера есть метка «резерв». Резерв берётся,
  только когда все основные не отвечают или сидят в карантине — так дешевле, чем
  держать в работе медленный запасной канал.
- Разбор конфига честный: если нет `[Peer]`, `PrivateKey` или `Endpoint` —
  покажем что именно, а не «ошибка парсинга».
- Тесты: Rust **112** (+7), фронтенд **77** (+2).

## Windows 1.11.0 — оркестратор, списки Zapret, игровой режим

- **Оркестратор (по мотивам zapret 2).** Приложение запоминает по каждой паре
  «сервер + транспорт», сколько было успехов и провалов, и считает счёт
  надёжности. Три провала подряд — сервер уходит в карантин на 10 минут, и
  автовыбор его больше не берёт. Первый успех возвращает его обратно.
  Данные лежат в `orchestrator.json` в данных приложения, есть кнопка сброса.
- **Проверка «туннель реально работает».** Пока VPN поднят, раз в 15 секунд
  идёт тихая проба (204-адреса Google и Cloudflare). Два провала подряд —
  переключение на живой сервер. Это ловит самую частую беду: «подключено, а
  сайты не открываются».
- **Импорт списков Zapret.** В «Маршрутизации» можно указать папку Zapret:
  приложение читает `lists/list-general.txt`, `list-google.txt`, списки
  исключений и (по желанию) `ipset-all.txt`, и превращает их в свои правила.
  Чужая папка только читается, ничего в ней не меняется.
- **Игровой режим.** Игровой и голосовой трафик (Steam, Discord RTC, STUN,
  Xbox, Riot) идёт напрямую, мимо туннеля: ниже задержка, голос не рвётся при
  переключении сервера. Список портов редактируется.
- Тесты: Rust **105** (+6), фронтенд **75** (+13).

## Windows 1.10.0 — автообновление

- **Обновление приходит само.** Через 12 секунд после запуска приложение тихо
  проверяет версию; если вышла новая — сверху появляется полоса с кнопками
  «Обновить сейчас» и «Позже». «Обновить» скачивает установщик, запускает его и
  закрывается, чтобы Windows дал заменить файлы.
- **Защита не обходится.** Если kill-switch включён, а VPN выключен, сеть закрыта
  и проверка молчит — никаких исключений в firewall для апдейтера.
- Тесты: Rust 95, фронтенд 62.

## Windows 1.9.0 — защита возвращается после перезагрузки, история автовыбора

- **Kill-switch включается после ребута.** При старте приложения, если галка
  «Kill-switch» включена, защита поднимается заново. Плюс ставится задача в
  планировщике Windows «K4R Neko VPN kill-switch»: helper стартует при входе в
  систему с правами администратора, даже если само приложение не запущено.
  Выключили галку — задача удаляется.
- **История автовыбора.** В настройках под автовыбором видны последние 5
  переключений: время и «откуда → куда». Хранится в `auto_history.json` в данных
  приложения, никуда не отправляется.
- Тесты: Rust 95, фронтенд 62.

## Windows 1.8.4 — helper нельзя убить без прав

- **DACL на процесс helper'а.** Раньше `taskkill /F /PID` от того же
  пользователя убивал helper без всякого UAC (так и показал CI smoke test), а
  вместе с ним снималась и защита. Теперь на процесс ставится DACL «только
  SYSTEM и администраторы»: ограниченный токен получает `Access is denied`,
  администратор по-прежнему может снять защиту через `--wfp-off`.
- Smoke test обновлён: проверка `taskkill` теперь ждёт отказа, а не смерти
  helper'а.
- Тесты: Rust **95**, фронтенд **62**.

## Windows 1.8.3 — самодиагностика kill-switch и CI smoke test

- **Кнопка «Проверить kill-switch»** в настройках: 7 автопроверок (sublayer в WFP,
  BLOCK на V4/V6, permit на адрес TUN, живой helper, DACL против непривилегированного
  процесса, цикл «снять/вернуть защиту» с проверкой интернета, правило TUN по LUID).
  Результат — списком с причиной; «Скопировать отчёт» кладёт текст в буфер.
- **`--wfp-dump`**: печатает JSON-снимок того, что реально лежит в WFP. Для
  диагностики и для CI — вместо разбора мегабайтов `netsh wfp show state`.
- **CI smoke test** (`.github/workflows/wfp-smoke.yml`, Windows runner с правами
  администратора): стартует helper, проверяет sublayer/фильтры/BLOCK, блокировку
  `curl` наружу, живой loopback и DNS, `--wfp-off`, переживание смерти родителя
  (Job Object) и отказ DACL непривилегированному процессу. Артефакты: `netsh`
  state, журнал helper'а, отчёт по пунктам.
- Helper при автономном запуске применяет стартовый план (раньше ставил только
  BLOCK): так его можно проверять без GUI. Резолвер задаётся `K4R_WFP_RESOLVER`.
- Тесты: Rust **95**, фронтенд **62** (без изменений — проверки требуют Windows).

## Windows 1.8.2 — ошибки списков маршрутизации

- **Понятные ошибки .srs (P1.4b).** Списки «Российские сайты» и «Реклама и трекеры»
  ядро качает само, и раньше любая беда выглядела как «движок не запустился». Теперь

  списка. В тексте — имя списка (`geosite-category-ru`), если ядро его сообщило, и
  что делать.
- При kill-switch on + VPN off к ошибке добавляется та же подсказка, что и для
  подписок: сеть закрыта намеренно, включите VPN или выключите блокировку.
- Тесты: фронтенд **62** (+10: разбор строк sing-box про rule-set).

## Windows 1.8.1 — автовыбор сервера и понятные ошибки

- **Автовыбор сервера (P1.3).** Настройки → «Автовыбор сервера»: выкл / 5 / 15 / 30 /
  60 мин плюс триггер «при потере соединения». По умолчанию **выключено**: у тех, кто
  уже выбрал сервер руками, поведение не меняется.
  - Переключаемся, только если другой сервер быстрее текущего **на 25%**. Шум замера по
    TCP-рукопожатию — ±10–15%, а каждое переключение это разрыв соединения: при 20%
    дёргаемся на шуме, при 30% терпим заметно худший сервер. 25% — середина.
  - Текущий сервер в топ-1 по замеру — не трогаем, равенство тоже в его пользу.
  - Активную закачку не рвём: больше 2 МБ/с в последнем замере — переключение
    откладывается до паузы.
- **Понятные ошибки загрузки списка (P1.4).** Причины разделены: нет сети, таймаут,
  502 от панели, прочий HTTP-отказ, невалидный JSON, пустой список, отказ провайдера.
  У каждой — свой текст с действием вместо «ошибка».
- **Kill-switch и первая загрузка списка.** При kill-switch on + VPN off сеть закрыта
  намеренно, поэтому в тексте ошибки теперь прямо сказано: «Заблокировано kill-switch:
  подключите VPN или выключите блокировку». Разрешение download-доменов в WFP **не
  добавлял**: домены панелей заранее неизвестны, а permit «443 куда угодно» — дыра в
  kill-switch. Подсказка честнее разрешения.
- **Fail-closed после рестарта GUI.** Helper жив → при старте приложения план
  переприменяется, галка остаётся включённой, интернет не возвращается сам. Снятие —
  только явным «Отключить kill-switch»/«Отключить VPN» или `--wfp-off`.
- **«Защита снята» — только при отказе watchdog'а**, с конкретной причиной в плашке
  (UAC отклонён, spawn failed, нет доступа), а не generic «сбой».
- **Job Object.** Перед запуском helper'а проверяется `IsProcessInJob`; если GUI попал в
  job с kill-on-close — `CREATE_BREAKAWAY_FROM_JOB`, иначе в журнал пишется, что
  fail-closed не гарантирован.
- CI: релизы теперь создаются **черновиками** (`gh release create --draft`).
- Тесты: Rust 95, фронтенд 52 (+9: автовыбор, разбор ошибок загрузки).

## Windows 1.8.0 — kill-switch на уровне ОС (WFP)

- **Защита больше не кончается вместе с приложением.** Отдельный helper-процесс
  держит динамическую сессию Windows Filtering Platform: фильтры живут в ядре и
  снимаются системой только вместе с helper'ом. Убил GUI — трафик наружу не
  уходит. Убил helper — система снимает фильтры сама, интернет возвращается.
- **Правила узкие:** loopback, локальная сеть, движок `sing-box`, TUN-интерфейс,
  DNS-резолвер (UDP/53, TCP/53, TCP/853), DoH — только на явно заданный IP.
  Всё остальное — BLOCK. «Любой порт» не разрешается нигде.
- **TUN-правило ставится по событию ОС** (`NotifyIpInterfaceChange`): туннель
  работает сразу после подключения, без окна «полсекунды без сети». Пока TUN
  нет, страхует permit на адрес TUN.
- **Пересборка транзакционная:** смена сервера или резолверов не оставляет
  систему без BLOCK; после каждой пересборки наличие BLOCK проверяется.
- **Канал helper'а защищён:** DACL (SYSTEM, администраторы, владелец) и
  проверка `TokenElevation` у клиента; непривилегированный процесс снять защиту
  не может. Аварийное снятие — `K4R Neko VPN.exe --wfp-off`.
- **Надзор:** helper упал — приложение поднимает его заново; не смогло — галка
  снимается, в интерфейсе красная плашка «Защита снята».
- Документация и чек-лист приёмки: `docs/kill-switch.md`.
- Тесты: Rust **95** (+11): план фильтров, стартовый план с BLOCK и #6b,
  семейства резолверов, DoH, TUN-правило, watcher, отказ непривилегированному
  клиенту канала.

## Windows 1.7.0 — Zapret вместе с приложением, обновления из коробки

- **«Запускать вместе с приложением»** на вкладке «Защита». Отдельная программа
  Zapret 2 Dev больше не нужна: приложение само поднимает выбранный пресет при
  старте. Чужой запущенный `winws2` по-прежнему не трогается — им управляет
  человек.
- **Проверка обновлений работает сразу.** Адрес манифеста версий прописан по
  умолчанию, и приложение само говорит, что вышла новая версия. Очистишь поле
  в настройках — проверять не будет (это выбор, а не поломка).
- Тесты: Rust **84** (+3): миграция адреса обновлений и сохранение ручной очистки.

## Windows 1.6.0 — маршрутизация: что в туннель, что напрямую, что в блок

- **Российские сайты — напрямую.** Один переключатель: домены и адреса РФ идут
  мимо туннеля (быстрее, меньше нагрузки на сервер), остальное — как обычно.
  Списки ядро скачивает и обновляет само, в установщик они не вшиты.
- **Реклама и трекеры — в блок.** Второй переключатель отклоняет известные
  рекламные и трекерные домены на месте.
- **Свои правила.** Домен, домен с поддоменами, слово в домене или подсеть
  (CIDR) → «в туннель», «напрямую» или «блок». Порядок строк — порядок
  применения, первое совпавшее решает; правила можно включать, выключать и
  двигать. Свои правила важнее разделения по программам: если человек сказал
  «этот домен напрямую», приложение не спорит.
- **Правила применяются при подключении** — на экране есть кнопка
  «Переподключить», чтобы применить сразу.
- Тесты: Rust **79** (+7, включая проверку конфига с правилами настоящим
  sing-box), фронтенд **35**.

## Windows 1.5.1 — подписка грузится у придирчивых панелей

- **502 от панели больше не «сервер сломался».** Провайдеры узнают клиента по
  `User-Agent` и незнакомому отвечают `502 Bad Gateway` от nginx. Своё имя
  (`K4R-Neko-VPN`) панели не знают, а `v2rayNG`, `Streisand`, `Hiddify` — знают.
  Теперь клиент пробует по очереди и останавливается на первом, кто отдал
  настоящие серверы; в предупреждениях честно пишет, каким клиентом получилось.
- **Слова провайдера важнее наших формулировок.** Если панель ответила заглушкой
  «Вы превысили лимит устройств: 5/5», человек видит эту фразу, а не
  «сервер ответил 502» и не «это YAML».
- **Заголовок устройства отправляется всегда**, как и раньше: без `X-HWID`
  некоторые панели взамен серверов присылают «приложение не поддерживается».
- `examples/sub_probe.rs` — маленькая диагностика: печатает, сколько серверов
  пришло, в каком формате и каким клиентом. Адрес сервера в вывод не попадает.
- Тесты ядра: **72** (+5): порядок клиентов и отсутствие повторов, приоритет
  понятной ошибки над технической.

## Windows 1.5.0 — сам подключается, сам переключается

- **Подключение при запуске.** Настройка «Подключаться при запуске»: туннель
  поднимается сам через полторы секунды после открытия приложения, чтобы окно
  успело появиться. По умолчанию выключено — клиент не лезет в сеть без просьбы.
- **Смена сети больше не убивает туннель молча.** Сторож раз в пять секунд
  смотрит, каким адресом система собирается идти наружу; сменился (Wi-Fi →
  кабель, другой Wi-Fi, выход из сна) — туннель перезапускается. Если человек
  сам его выключил, сторож ничего не включает. После перезапуска 20 секунд
  тишины, чтобы одна и та же заминка не вызвала лавину переподключений.
- **Деградация: сервер «жив», а данные не идут — переключаемся сами.** Раз в
  15 секунд проверка через туннель; три неудачи подряд — берём следующий сервер
  из подписки. Через минуту после переключения проверяем снова. Выбор владельца
  при этом не перезаписывается: это обход на время.
- **Серверы и состояние в трее.** В меню значка — до шести серверов с отметкой
  выбранного, клик выбирает и поднимает туннель. Подсказка значка говорит
  состояние и сервер: «Защищено · Токио».
- **Срок и остаток подписки на главном экране.** «Подписка до 05.12.2026 · 19 дн.»,
  «Остаток 24 ГБ из 50 ГБ». Три дня и меньше — предупреждение цветом, истекла —
  прямо говорит, что истекла. Если провайдер молчит, строки нет: выдуманная дата
  хуже пустого места.
- **Понятная причина вместо кода выхода.** Не поднялся туннель — сначала
  проверяем, есть ли вообще интернет (нет → «нет интернета: проверь Wi-Fi или
  кабель»), потом дозваниваемся до самого сервера (не отвечает → «сервер «Токио»
  не отвечает»). Раньше в обоих случаях человек видел «движок завершился с кодом 1».
- Тесты ядра: **67** (+12): решение об автоподключении, смена сети, порядок
  серверов при переключении, адрес сервера из конфига и причина отказа словами.

## Windows 1.4.0 — обновляемое ядро и подписки в JSON

- **Ядро туннеля можно обновить из настроек.** Панель «Ядро» показывает версию,
  которую называет сам sing-box (`sing-box version`), кнопка спрашивает GitHub,
  какая версия последняя, и ставит её рядом с настройками приложения — без прав
  администратора, не трогая установленную программу. Кнопка «Вернуть встроенное»
  удаляет обновление. Скачанное проверяется запуском: если файл не отвечает
  версией, он не подменяет рабочее ядро.
- **Подписки понимают формат sing-box JSON** (`{"outbounds":[{"type":"vless",…}]}`)
  наравне со списком `vless://` и форматом Xray: переносы ws/grpc, REALITY, uTLS,
  flow. «Импорт ссылки» принимает конфиг целиком.
- Тесты ядра: **55** (+7): сборка адреса релиза (и отказ на всём, что не версия),
  чтение версии из вывода ядра, json подписки.

## Пока не релиз — подписки в формате sing-box JSON

- **Разбор подписок расширен**: провайдер может отдать конфиг sing-box
  (`{"outbounds":[{"type":"vless",...}]}`) — теперь он читается наравне со
  списком ссылок `vless://` и форматом Xray. Переносы ws/grpc, REALITY
  (public_key, short_id), uTLS-отпечаток, flow — всё на месте.
- **«Импорт ссылки» принимает целый конфиг**: вставка JSON идёт тем же разбором,
  что и подписка, а не отдельной веткой.
- 52 теста ядра (+4): reality из sing-box JSON, ws-транспорт, отказ без серверов,
  вставка конфига как ссылки.

## Windows 1.3.0 — кружок вместо кнопки, один экземпляр, журнал с потолком

- **Включение нажатием на кружок.** Отдельной кнопки «Включить VPN» больше нет:
  маскот и есть кнопка. Под кружком подпись словами («Нажми, чтобы включить» /
  «Нажми, чтобы выключить» / «Поднимаем туннель»), цвет подписи повторяет
  состояние. `aria-label` теперь говорит и состояние, и действие — экранный
  диктор не читает одно слово.
- **Один экземпляр приложения.** Двойной запуск больше не поднимает второе ядро:
  второй процесс стучится на `127.0.0.1:39311`, первый показывает окно, второй
  выходит. Порт-сторож держится, пока жив процесс, и освобождается сам. Чужой
  сервис на этом порту не мешает запуску — тогда просто нет защиты от второго окна.
- **Потолок журнала.** `engine.log` пишется дозаписью без ограничения, а ядро
  добавляет строки на каждый запуск. Теперь после 4 МБ файл уезжает в
  `engine.log.1` (хранится один предыдущий кусок), ротация происходит до старта
  ядра — на Windows переименовать открытый файл нельзя.
- Тесты: ядро **48** (было 40): 4 на сторож одного экземпляра, 4 на ротацию.

## Android 0.3.0 — несколько подписок, трафик по дням, спидтест

- **Несколько подписок.** Раньше одна ссылка затирала предыдущую. Теперь
  подписки хранятся списком: плашки подписок на главной, «Добавить подписку»,
  «Забыть эту». Действующая запоминается, вместе с ней поднимаются её серверы.
  Старая одиночная подписка переносится в список при первом запуске, ничего не
  теряется. Подпись плашки — название от провайдера, а если его нет — адрес с
  путём: у одного провайдера бывает несколько подписок на одном хосте.
  Проверено на устройстве: две подписки, переключение, удаление, подключение.
- **Трафик по дням.** Счётчики ядра складываются в историю за 30 дней: столбики
  за неделю и сумма. Цифры берутся у ядра (байты интерфейса), а не у провайдера,
  и пишутся на диск раз в 20 секунд, чтобы не дёргать его каждую секунду.
- **Спидтест через туннель**: качаем пробный файл на 5 МБ и показываем мбит/с.
  Приложение держится внутри туннеля, иначе и спидтест, и проверка IP мерили бы
  прямое соединение и врали бы: при разделении «только выбранные» оно добавляет
  себя в список выбранных.
- **Остановку ядра видно.** Если ядро умирает уже после подключения (ошибка,
  отказ сервера), приложение больше не продолжает показывать «Защищено»: оно
  честно переходит в «Ошибка» и, если включён kill switch, держит трафик.
  Обычное выключение человеком сбоем не считается.
- **«Проверить все» в списке серверов**: отклик всех серверов разом, по три
  соединения за раз. Проверено на устройстве: живой порт — 14 мс, мёртвый —
  «нет ответа».
- **Ссылка из буфера одной кнопкой** — на телефоне вставлять долгим нажатием
  неудобно. Буфер читается только по нажатию: иначе система сообщает, что
  приложение читает буфер, при каждой перерисовке экрана.
- **Разделение по программам не превращается в «только это приложение».**
  Проверка IP и спидтест должны идти через туннель, поэтому приложение
  добавляло себя в список разрешённых — но по правилам Android непустой список
  означает «только эти», и при пустом выборе в туннель попадало бы одно
  приложение. Теперь себя добавляем только тогда, когда человек выбрал
  конкретные программы. Правило вынесено в `data/Split.kt` и покрыто тестами.
- **Проверено живьём на настоящем туннеле** (свой сервер sing-box на ПК):
  «Защищено» только после ответа данных, IP через туннель, счётчики ядра,
  спидтест 6.7 Мбит/с внутри туннеля, учёт трафика 4.8 МБ за день, отказ
  сервера → «Ошибка» + блокировка (запрос из приложения при этом не проходит),
  «Вернуть интернет» → сеть возвращается. После перезагрузки телефона туннель
  поднялся сам (автозапуск), а учёт трафика продолжился с того же дня.
- **Причина заглушки переводится в действие.** Провайдер отвечает одинаково:
  сервер на `0.0.0.0:1`, а причина — в названии. Теперь «предел устройств»
  превращается в «удалите лишнее устройство в кабинете и нажмите Load»,
  «подписка истекла» — в «продлите и нажмите Load», а не в чужой текст.
- **Ссылку подписки можно скопировать** одной кнопкой — чтобы перенести на
  другой телефон. Кнопки «Вставить из буфера» и «Копировать» видны и на первом
  запуске, когда подписок ещё нет: именно тогда вставка и нужна.
- **Резервная копия настроек**: подписки, DNS, тема, язык, разделение и учёт
  трафика сохраняются в JSON-файл и восстанавливаются на другом телефоне.
  Чужой файл и файл будущей версии отвергаются с понятным сообщением, а не
  «что-то пошло не так».
- **Журнал переживает падение.** События ядра и службы теперь пишутся ещё и в
  файл (до 200 КБ, с обрезкой по целой строке), а падение приложения оставляет
  в журнале строку `СБОЙ` со стеком. В настройках видно, сколько строк на диске,
  и есть кнопка «Отправить журнал» — уходит текстом с шапкой (версия, Android,
  модель телефона), без файлов и лишних разрешений.
- **106 юнит-тестов** на JVM: подписки (хранение, порядок, переключение),
  история трафика (сложение, границы, окно недели), скорость (арифметика),
  резервная копия, причины заглушки провайдера, обрезка журнала. Всего в проекте 106 тестов
  Android, 41 тест ядра ПК (40 идут, 1 помечен `ignored`) и 25 тестов
  интерфейса ПК.

## Android 0.2.0 — защита при обрыве, язык, журнал

- **Защита при обрыве (kill switch).** Если сервер не ответил или туннель упал,
  трафик больше не уходит напрямую: поднимаем VPN без ядра, маршруты забирают
  всё, читать их некому — пакеты пропадают. Кнопка на главной меняется на
  «Вернуть интернет», иначе человек остался бы без сети и без объяснения.
  Проверено живьём: мёртвый сервер → IP-проверка виснет, «Вернуть интернет» →
  домашний адрес виден снова.
- **Перебор серверов.** Провайдер кладёт в список «Авто-выбор сервера» с чужим
  адресом, и на живом списке он не отвечал. Теперь при отказе пробуем следующий
  сервер (до трёх), «Авто-выбор» — в конце очереди, а после загрузки подписки
  выбирается первый настоящий сервер. В интерфейсе видно, какой пробуем.
- **Честная проверка готовности.** Сначала считали живым «сокет открылся», но
  ядро принимает соединение само и соглашается даже с мёртвым сервером —
  получалось «Защищено» при мёртвом туннеле. Теперь проверяем, пришли ли
  настоящие данные, по адресу (без DNS) и с жёстким сроком 5 секунд: вердикт
  за ~15 секунд вместо ~100.
- **Язык выбирается в приложении**: как в системе / русский / English. Язык
  применяется до первого кадра, поэтому подписи не «прыгают».
- **Журнал ядра в настройках** — последние 200 событий: какой сервер пробовали,
  что ответило ядро, почему отказ. Обновляется раз в секунду, пока открыт.
  Адреса серверов в журнал не попадают.
- **Отклик серверов в списке**: при выборе меряем время TCP-соединения —
  «5 мс» или «нет ответа». Это цифра «сколько ждать до сервера», а работает ли
  через него туннель, по-прежнему решает проверка запуска.
- **Постоянный `X-HWID`** считается из `ANDROID_ID`: переустановка приложения
  больше не занимает у провайдера новый слот устройств.
- **61 юнит-тест** на JVM: разбор подписки (base64, REALITY, gRPC, заголовки
  трафика), флаги стран, конфиг ядра, сборщик JSON, выбор серверов, отклик,
  журнал, язык, HWID. Тесты нашли две настоящие ошибки: «It works» теряло слово
  («IT» принималось за Италию), а неизвестный код рисовал несуществующий флаг.
- Конфиг ядра теперь собирается своим сборщиком JSON с экранированием по
  RFC 8259: `org.json` в юнит-тестах — заглушка, и конфиг было нечем проверить.
- `base64` разбирается `java.util.Base64` и принимает URL-safe алфавит и строки
  без выравнивания по «=».
- Кнопка в настройках «Защита при обрыве»: включена по умолчанию.
- **Исправлено по итогам проверки на устройстве**: после отказа туннеля
  VPN-интерфейс оставался включённым (нет интернета при состоянии
  «Выключено»); автозапуск после перезагрузки падал на Android 15
  (служба типа `dataSync` запрещена по `BOOT_COMPLETED` — теперь `specialUse`);
  переключение языка через `LocalContext` в Compose валило приложение.
- Адрес выхода запрашивается сам, как только туннель поднялся.
- **Сам поднимается, когда возвращается сеть.** Пока трафик заблокирован, служба
  ждёт появления обычной сети (без VPN) и пробует подключиться снова — не больше
  трёх раз. Проверено переключением авиарежима: в журнале «сеть вернулась —
  пробуем ещё раз», подключение пошло само.

## 1.0.0 — первая релизная версия для Windows

Первая версия, которую можно ставить людям. Всё, что ниже, проверено на живой
машине: подключение, разделение по программам, блокировка при обрыве,
переподключение, установка и удаление.

**Туннель**
- VLESS + Reality + gRPC через sing-box, несколько подписок, выбор сервера.
- Проверка живости серверов параллельно; не ответивший помечается «не отвечает».
- Автопереподключение при обрыве, до трёх попыток.

**Разделение по программам**
- Два режима: «Только выбранные» и «Все, кроме выбранных».
- Локальная сеть и принтер остаются локальными в любом режиме.
- Пустой список «В VPN» — отказ подключения, а не фиктивная защита.

**Блокировка при обрыве**
- Движок падает — поднимается «держащий» режим: наружу ничего не уходит,
  локальная сеть работает. Откат — один переключатель, следов в системе нет.

**DNS**
- Свой резолвер внутри туннеля: адрес, `https://` (DoH) или `tls://` (DoT).

**Настройки и мелочи**
- Автообновление подписки: 1/3/6/9/12/24/48 часов или вручную.
- Проверка новой версии по файлу с описанием.
- Горячая клавиша, автозапуск, крестик и «—» в трей, карточка-уведомление.
- Три темы (тёмная, светлая, маскот), два языка (ru/en), экспорт журнала.
- Свой ID устройства, счётчики трафика из движка, а не нарисованные.

**Zapret рядом**
- Приложение читает состояние чужого `winws2` и никогда его не трогает.
